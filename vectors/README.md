## `ldpc_<code>.json` (header, control, data)

One file per code. Top-level fields: `format` (`cairn-ldpc-vectors`),
`version`, `license`, `code`, `base_graph`, `lifting` (Z), `message_bits`,
`info_bits` (message plus CRC-16), `codeword_bits` (N before puncturing, as in
`codes/*.alist`), `coded_lengths`, and `vectors`.

Each vector has:

- `name`: `zeros`, `ones`, `counting` (byte i is i mod 256) or `randomN`
  (N = 1, 2, 3: bytes of SHA-256 of the ASCII string
  `cairn-ldpc-vector:N:counter`, counter = 0, 1, ... concatenated).
- `message_hex`: the message bytes (128, 240 or 1008 bits).
- `info_hex`: message followed by its CRC-16/CCITT-FALSE (poly 0x1021, init
  0xFFFF, no reflection, no final XOR; computed over the message bits, sent
  most significant bit first, big-endian). This is the code's information
  bits (144, 256 or 1024).
- `codeword_hex`: the full systematic codeword of N bits: information bits,
  then K - K' zero filler bits, then parity. Includes the punctured bits.
- `rate_matched_hex`: map from on-air length E to the E bits sent, i.e. the
  codeword bits selected by `codes/<stem>_ratematch.txt`, in order.

Bit order: every `*_hex` field packs bits big-endian. The first bit is the
most significant bit of the first byte; a final partial byte is padded with
zero bits (only `codeword_hex` of the header code, N = 780, has padding). A
bit value of 0 is sent as +1 by BPSK; the vectors do not depend on this.

## `bitmap/<case>.json` (ADR 0005 bit mapping)

Generated by `uv run --package cairn-sim python -m cairn_sim.bitmap_vectors`
(`sim/cairn_sim/bitmap_vectors.py`); do not edit by hand. Each file follows
one frame through every stage of ADR 0005, from payload to tone values and,
for three cases, to time-domain samples. `sim/tests/test_bitmap_vectors.py`
regenerates them byte for byte and checks each stage against the rules,
written out independently of the simulator.

| Case | Width | MCS | Data blocks | Prefix | Mask (tones off) | Samples |
| --- | --- | --- | --- | --- | --- | --- |
| `w24_mcs0` … `w24_mcs6` | 24 | 0–6 | 2 | 60 | none | `w24_mcs6` only |
| `w24_mcs0_long` | 24 | 0 | 1 | 120 | none | yes |
| `w24_mcs3_long_masked` | 24 | 3 | 2 | 120 | 0, 1, 2 | no |
| `w30_mcs1_masked` | 30 | 1 | 2 | 60 | 9, 25 (and 40, above the width, ignored) | no |
| `w56_mcs2`, `w56_mcs6` | 56 | 2, 6 | 2 | 60 | none | no |
| `w56_mcs4_long_masked` | 56 | 4 | 2 | 120 | 0, 1, 2, 37 (a pilot), 45, 46 | yes |

Frames wider than 24 tones carry the two-symbol width probe after the
header, with the probe width equal to the link width. There are no control
blocks here; `frame/` below has frames with them.

Inputs are pseudo-random bytes: SHA-256 of the ASCII string
`cairn-bitmap-vector:<case>:<item>:<counter>`, counter = 0, 1, …,
concatenated, with item `header` (16 bytes, the header's 128 bits before
its CRC) or `block<i>` (126 payload bytes of data block i). The header bits
are arbitrary and do not follow the SPEC 8.2 field layout; the bit mapping
does not depend on them.

Top-level fields:

- `format` (`cairn-bitmap-vectors`), `version`, `license`, `name`.
- `width` (W), `mcs`, `modulation`, `bits_per_point` (Q), `code_rate`,
  `coded_bits` (E of each data block), `interleaver_a` (a for E),
  `prefix_samples` (60 or 120).
- `usable_tones`: the 56-bit mask report as a list of usable tones, or
  `null` for no mask. `masked_tones`: the tones below the width it turns
  off.
- `control_blocks` (always 0), `data_blocks`, `total_symbols`.
- `segments`: in frame order, each with `kind` (`preamble`, `header`,
  `probe`, `data`), `first_symbol` (s, counted from the first preamble
  symbol), `symbols`, and either `tones` (preamble, probe) or
  `data_tones` and `pilot_tones` (lowest first) and `gain` (the scale on
  every active tone of the segment's symbols).
- `header`: `position` (0), `c_init`, `coded_bits` (288), `interleaver_a`,
  `message_hex`, then the stages below, plus `pad_bits`, `pad_hex` (the
  padding that completes the header's last symbol) and `points_iq`.
- `blocks`: one per data block, with `index`, `position` (1 + index),
  `c_init` (1 + position), `first_symbol_offset` and `first_tone_slot`
  (where the block's first point lands, relative to the first data symbol
  and as an index into the data tones), `payload_hex`, then the stages
  below.
- `data`: `pad_bits` and `pad_hex` (the padding after the last block),
  `point_scale` (1/√2, 1/√10, 1/√42 or 1/√170), and `points_iq`, the points of
  the whole data segment: blocks, then padding.
- `grid`: `re` and `im`, each `total_symbols` rows of W values: the tone
  values X[k] of every symbol, with gains applied, before the time-domain
  scale. Printed to 9 decimal places.
- `samples_scale` and `samples` (three cases only): the frame's
  time-domain samples at 48 kHz, symbol after symbol, each symbol being
  prefix plus useful part, x(n) = A·Re{Σ X[k]·exp(j2π(3.5 + k)n/480)} with
  A = `samples_scale` = √(2/W), and no clip-and-filter (the clipper is not
  bit-exact and its level depends on the rung, ADR 0003). Printed to 6
  decimal places. The scale is the simulator's (unit mean power for W
  unit-power tones); only the relative values are normative.

Per-block stages, as big-endian hex like the LDPC vectors:

- `info_hex`: payload (or header message) followed by its CRC-16.
- `rate_matched_hex`: the E bits after LDPC encoding and rate matching
  (identical to `rate_matched_hex` of the LDPC vectors for the same
  information bits).
- `scrambler_hex`: c(0 … E−1), the Gold sequence for this block's
  `c_init`.
- `scrambled_hex`: `rate_matched_hex` XOR `scrambler_hex`.
- `interleaved_hex`: the scrambled bits permuted, scrambled bit i at
  position (a·i) mod E.

`points_iq` lists the constellation points before scaling as odd integers,
I then Q for each point (I0, Q0, I1, Q1, …). Multiply by `point_scale` (1/√2 for
the header, always QPSK) and the segment `gain` to get the tone values in
`grid`. Point m of a segment
lies in symbol ⌊m/D⌋ of the segment, on `data_tones[m mod D]`.

## `header/<case>.json` (SPEC 8.2, B.1)

Generated by `uv run --package cairn-sim python -m cairn_sim.frame_vectors`
(`sim/cairn_sim/frame_vectors.py`, with `header/`, `control/` and `frame/`);
do not edit by hand. `sim/tests/test_frame_vectors.py` regenerates them byte
for byte and packs every valid case from its fields with the SPEC tables
written out independently of the simulator.

Fields: `format` (`cairn-header-vectors`), `version`, `license`, `name`,
`description`, `valid`, then either `fields` (valid cases) or `error`
(`crc` or `fields`: a header a receiver must discard), and `message_hex`
(the 128 bits before the CRC) and `info_hex` (all 144 bits), big-endian hex
as above.

`fields`: `version`, `frame_type`, `flags` (the 8-bit field's value),
`more_fragments`, `session`, `probe`, `repeat` (flag bits 2-5),
`source` and `destination`, `sequence`, `mcs`, `control_blocks` (0-3) and
`data_blocks` (0-128; sent as count − 1 when flag bit 1 is set, as 0
otherwise). Flag bits 0 and 1 are set exactly when the control and data
block counts are nonzero. An address is `{callsign, ssid, value_hex}` (the
40-bit field), `{callsign, hash30, ssid, value_hex}` for a 7-10 character
callsign sent as code 63 and its hash (a receiver recovers only `hash30`),
or `{broadcast: true, value_hex: "ffffffffff"}`.

| Case | Content |
| --- | --- |
| `beacon` | BEACON to broadcast, one control and one data block |
| `ui_fragment_repeat` | UI, more-fragments and repeat flags, MCS 3, 128 data blocks, sequence 65535 |
| `connect`, `connect_ack`, `data`, `ack` | Session frames: probe, session flag, three control blocks, MCS 6 |
| `probe_long_callsign` | PROBE from `N0CALL/7`, a hashed callsign |
| `extended_mcs_ignored` | Type 31 with MCS field 15 and no data blocks (valid: the field is ignored) |
| `reject_crc` | CRC failure |
| `reject_flag0_mismatch` | Flag bit 0 clear with two control blocks (SPEC 8.2: discard) |
| `reject_version` | Version 2 |
| `reject_address_code` | A reserved character code (39) in the source address |

## `control/<case>.json` (Appendix B)

Same layout with `format` `cairn-control-vectors`, 240-bit `message_hex`
and 256-bit `info_hex`, and `error` `crc`, `fields` (malformed: discard the
block) or `unknown` (a reserved control type: skip the block and process
the rest of the frame). `fields` has `type` and, by type:

- 0 ACK (B.2): `base_sequence`, `bitmap_hex` (the 128-bit field; bit i, of
  weight 2^i, is block base + i), `requested_mcs`, `snr_q` (0.25 dB
  steps), `block_errors`, `tone_mask` (usable tones, or `null` when flag
  bit 0 is clear and the field is sent as zeros), `reprobe` (flag bit 2),
  `long_prefix` (flag bit 3), `distortion`, `adc_clipped`.
- 1 CONNECT / CONNECT-ACK (B.3): `session_id`, `capabilities`, `width_cap`,
  `requested_mcs`, `max_frame_time`, `tone_mask`, `dictionary_ids` (four
  slots, the first in the most significant bits), `more_dictionaries`
  (flag bit 0), `resume` (flag bit 1).
- 3 CAL-REQUEST (B.5): `tone_freq`, `step_count`, `step_length`,
  `gap_length`, `start_level`, `step_size`.
- 4 CAL-REPORT (B.5): `amplitudes` and `distortion` (steps 1-8, step 1 in
  the most significant bits), `clipped` (step j at bit j − 1),
  `sweep_valid`.
- 5 ID (B.6): `callsign` (ten ASCII characters, space-padded), `ssid`,
  `grid` (`null` when absent; the field is then zeros).
- 6 Path (B.7): `entries` (0-2 addresses as above; unused entries are
  zeros), `hops`, `used` (flag bits 0 and 1), `via` (flag bit 2).

A tone mask lists usable tones; tone k is bit k (weight 2^k) of the 56-bit
field. Cases: `ack`, `ack_mask_flags` (every field at an extreme),
`connect`, `connect_ack_resume`, `cal_request` (the B.5 defaults),
`cal_report`, `id_grid` (a 7-character callsign and a locator),
`id_no_grid`, `path`, and `reject_crc`, `reject_width_cap` (width cap 10),
`skip_reserved_type` (type 7).

## `frame/<case>.json` (whole frames with real headers and control blocks)

Whole frames in the `bitmap/` format, built from SPEC 8.2 headers and
Appendix B control blocks. Additions to that format:

- `header.fields`: the header's fields as in `header/`.
- `clip_db`: the clip level the frame uses on air, the data rung's or
  7 dB without data blocks (SPEC 7.1; the vectors themselves are before
  clip-and-filter).
- A `control` segment between the probe (if any) and the data: `data_tones`
  are tones 0-23 less pilots 3 and 20 and less masked tones, `pilot_tones`
  [3, 20], `gain` √(24 / (data tones + 2)) (ADR 0005), `symbols`
  ⌈512 · n / (2 · data tones)⌉.
- `controls`: one per control block, with `index`, `position` (1 + index),
  `c_init`, `first_symbol_offset` and `first_tone_slot` (relative to the
  first control symbol), `fields` as in `control/`, `message_hex`, and the
  per-block stages as above at E = 512 (interleaver a = 317).
- `control`: `pad_bits`, `pad_hex`, `point_scale` (1/√2) and `points_iq` of
  the control segment.
- Data blocks take positions 1 + n_control + index. A frame without data
  blocks has no `data` segment or section; `mcs`, `coded_bits` and the
  rest describe MCS 0 there and carry nothing.

Payload bytes come from SHA-256 of `cairn-frame-vector:<case>:block<i>:<counter>`.

| Case | Type | Width | MCS | Control blocks | Data blocks | Prefix | Mask (tones off) | Samples |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `connect_w30` | CONNECT | 30 (probe) | — | CONNECT, ID | 0 | 60 | none | no |
| `connect_ack_resume_probe` | CONNECT-ACK | 24 (probe) | — | CONNECT (resume), ACK | 0 | 60 | none | no |
| `data_ack_w24_mcs2` | DATA | 24 | 2 | ACK | 2 | 60 | none | no |
| `data_ack_w30_mcs3_long_masked` | DATA | 30 (probe) | 3 | ACK with mask | 3 | 120 | 1, 9, 25 (and 40, ignored) | no |
| `data_three_controls_w56_mcs4` | DATA | 56 (probe) | 4 | ACK, ID, CAL-REPORT | 2 | 60 | none | no |
| `ack` | ACK | 24 | — | ACK | 0 | 60 | none | yes |
| `probe_header_only` | PROBE | 24 | — | none | 0 | 60 | none | yes |

## Field readings

Where the SPEC leaves an encoding open, the vectors follow these readings
(also in `sim/cairn_sim/fields.py`):

- "Bit n" of a field has weight 2^n (bit 0 is the least significant and is
  sent last). One-bit-per-item fields put item i at bit i: the ACK bitmap
  (block base + i), the tone masks (tone k), CAL-REPORT clip flags (step j
  at bit j − 1). Sequences of multi-bit items put the first item in the most
  significant bits, as B.1 does for callsign characters.
- Absent optional fields (ACK tone mask without flag bit 0, ID grid locator
  without flag bit 0, unused path entries) are sent as zeros and ignored.
- Reserved bits are sent as zero and ignored on receipt; a header whose
  version is not 1 is discarded.
- A header with no data blocks sends its MCS field as given (0 by
  convention) and the receiver ignores it.
- Callsigns use the B.1 alphabet; a 7-10 character callsign is hashed.
  Reserved character codes, padding before a character, code 63 outside the
  first position and an empty callsign are malformed.
- The ACK's measured SNR is rounded to the nearest 0.25 dB (halves up) and
  saturates at 0 and 63.75 dB.
- The ID block's grid locator is 4 or 6 characters, space-padded to 6.
